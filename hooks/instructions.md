## 작업 진행 방식 (muwi)

파일을 고치는 작업을 맡으면, 첫 수정 전에 이번 작업을 어떻게 진행할지 계획을 짜서 `muwi` 명령으로 적는다. 사람은 이 기록을 그래프로 보면서 지금 무슨 일이 일어나는지 확인한다. 적지 않으면 사람에게는 아무것도 보이지 않는다. 순서와 방법은 정해져 있지 않다. 이번 작업에 맞게 직접 정한다.

- 시작할 때: 계획(노드와 순서)을 짜서 `muwi plan --work <이름> --request "<시킨 말>" '<계획 JSON>'`으로 적는다. 작은 작업이면 노드 두세 개로 충분하다.
- 진행하면서: 노드를 시작할 때 `muwi node <id> start`, 끝낼 때 `muwi node <id> done "<결과 한 줄>"`.
- 노드를 누가 할지(직접, 서브에이전트, 새 세션)와 새 세션을 어디에 보여 줄지도 스스로 정한다. 정했으면 계획의 노드에 `run`과 `show`로 적는다. 새 세션은 `muwi run <id> "<맡길 일>"`로 띄운다.
- 계획이 바뀌면: 바뀐 계획을 이유와 함께 다시 적는다 (`muwi add`, `muwi remove`, `muwi plan --why`). 사람이 바꾸라고 했으면 `--human`을 붙인다.
- 사람의 결정이 필요해 멈출 때: `muwi node <id> wait "<물어볼 것>"`으로 적고 묻는다. push, PR 생성, PR 댓글처럼 되돌릴 수 없는 행동은 사람이 승인한 뒤에 한다.
- 계획을 만들지 않는 경우: 질문에 답하기, 조사만 하기, 오타처럼 한 곳만 고치는 일. 그런 일에서 파일을 고쳐야 하면 `muwi skip "<이유>"`로 계획 없이 진행한다고 밝힌다.
- 이어가는 요청("아까 그거")이면 `muwi status`로 기존 작업부터 찾는다.
- 다른 세션이 맡긴 노드를 하는 중이면 계획을 새로 만들지 않고, 맡은 노드의 시작과 끝만 적는다. 맡은 일을 쪼개야 하면 `muwi add`로 같은 계획에 노드를 넣는다.
- 계획 JSON의 모양, 서브에이전트와 새 세션에 맡기는 방법, 일하면서 지킬 원칙(작업 위치, 독립 확인, 사람에게 묻는 방법), 지난 작업의 문제를 진단하는 방법은 muwi skill에 있다. 이 세션에서 처음 계획을 적기 전에 한 번 읽는다. `muwi` 명령이 없으면 기록 없이 평소대로 진행한다.
