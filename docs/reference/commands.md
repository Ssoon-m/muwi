# 명령어

`muwi` 명령의 사용법, 옵션, 환경 변수를 정리했습니다.

사용자가 직접 쓰는 명령은 [보기](#보기)와 [설치와 설정](#설치와-설정)입니다. 나머지는 AI가 일하면서 실행합니다. 사용자가 직접 실행해도 같은 방식으로 기록됩니다.

명령은 모두 코어(`@muwi/core`)에 있습니다. 보기가 더하는 명령도 있습니다. Herdr 앱 보기(`@muwi/herdr-app`)는 `muwi open`과 `muwi layout`을 더합니다. 새 세션에 맡기는 명령(`muwi run` 등)은 터미널 연결(예: `@muwi/herdr`)이 붙어 있을 때 동작합니다. 붙어 있지 않으면 무엇이 필요한지 알립니다.

어느 명령이든 `--help`를 붙이면 실행하지 않고 사용법만 보여 줍니다.

## 작업을 고르는 규칙

명령은 다음 순서로 작업을 정합니다.

1. `--work <이름>` 옵션 또는 `$MUWI_WORK`
2. 그 세션이 붙어 있는 작업

세션은 계획을 적거나 `--work`를 한 번 붙이면 그 작업에 붙습니다. 그 뒤로는 `--work`를 생략할 수 있습니다.

기록하는 명령(`add`, `remove`, `node`, `flag`, `run`, `tell`, `tidy`)은 붙어 있는 작업이 없으면 `--work`를 요구합니다. 보기만 하는 `muwi show`는 현재 폴더에서 시작한 작업이 하나면 그 작업을 보여 줍니다.

작업 이름에는 한글, 영문, 숫자, `.`, `_`, `-`를 쓸 수 있고 80자까지입니다. `<저장소>-<작업키>` 형식을 권장합니다 (예: `shop-web-PROJ-123`).

## 보기

| 명령 | 설명 |
| --- | --- |
| `muwi status [--all] [--json]` | 작업 목록을 보여 줍니다. 사용자를 기다리는 작업이 위에 나옵니다. 지난 작업과 보관한 작업은 빠지고 `--all`을 붙이면 모두 나옵니다 |
| `muwi archive <작업>…` 또는 `muwi archive --done` | 끝났거나 멈춘 작업을 목록(그래프 칸, `muwi status`)에서 치웁니다(보관). 기록과 작업 폴더의 파일은 그대로라 `muwi show`로 볼 수 있습니다. 보관한 뒤에 그 작업을 다시 시작하면 목록으로 돌아옵니다. `--done`은 끝난 작업을 모두 보관합니다. 하는 중인 작업은 보관하지 않습니다 |
| `muwi unarchive <작업>…` | 보관한 작업을 목록으로 꺼냅니다 |
| `muwi delete <작업>…` 또는 `muwi delete --archived` | 보관한 작업을 지웁니다 (끝 → 보관 → 삭제). 작업 폴더를 통째로(계획·기록과 그 폴더에 둔 파일까지) 휴지통 `~/.muwi/.trash`로 옮기고, 30일이 지난 것은 그 뒤에 muwi가 휴지통을 볼 때 비웁니다. `--archived`는 보관한 작업을 모두 지웁니다 (작업 이름과 같이 주지 않습니다). 보관하지 않은 작업이 하나라도 있으면 아무것도 지우지 않습니다 |
| `muwi restore [<작업>…]` | 지운 작업을 휴지통에서 되살립니다 (같은 작업을 여러 번 지웠으면 가장 최근 것). 보관한 채로 돌아오므로 보관함에 있습니다. 같은 이름의 작업이 있으면 되살리지 않습니다. 작업 없이 부르면 휴지통 목록과 남은 날을 보여 줍니다. 지운 작업을 하던 세션은 그 작업에 더 적지 않고, 그 이름으로 계획을 다시 적으려 하면 되살리라고 알립니다 |
| `muwi show [<작업>] [--json]` | 작업 하나의 기록을 보여 줍니다: 노드, 회차, 누가 했는지, 읽은 skill, 계획이 바뀐 기록, 빠진 노드, 문제 표시 |
| `muwi session` | 현재 세션이 붙어 있는 작업과 읽은 skill을 보여 줍니다 |
| `muwi guide` | 작업 진행 방식(지침)의 원본을 보여 줍니다. muwi가 업데이트돼 지침이 바뀌면 그 세션의 다음 적는 명령(`plan`, `node` 등) 출력 끝에도 한 번 붙습니다 |
| `muwi --version` | 버전을 보여 줍니다 |

`--json`을 붙이면 같은 내용을 JSON으로 출력합니다.

## Herdr 앱 화면 (`@muwi/herdr-app`)

| 명령 | 설명 |
| --- | --- |
| `muwi open` | Herdr 앱에서 그래프 칸을 현재 터미널 아래에 엽니다. 그 탭에서만 보입니다. 0.10까지 있던 `--right`는 없어졌습니다 |
| `muwi layout` | 지금 레이아웃을 복제해서 사이드바의 Agents 자리에 작업 목록을, 터미널 아래에 그래프를 넣고 그 레이아웃으로 바꿉니다. 원래 레이아웃은 그대로 남습니다. 이미 muwi 칸이 있으면 그대로 둡니다. Herdr가 업데이트된 뒤에 실행하면 새 모양으로 다시 만듭니다. Herdr 설정 화면(Look > Layout)에 보일 그림(`layouts/<이름>.svg`)도 같이 씁니다 |
| `muwi layout --graph bottom\|top` | 그래프 칸을 터미널 아래, 위에 둡니다. 고른 자리를 기억하고, 설정 화면의 그림도 그 자리대로 바꿉니다. 그래프 칸 오른쪽 위의 `위 · 아래` 버튼과 같습니다. 0.10까지 있던 `right`는 없어졌습니다 |
| `muwi layout --status [--json]` | 지금 화면에 muwi 칸이 있는지, 넣을 자리가 있는지 보여 줍니다 |
| `muwi layout --remove` | 원래 레이아웃으로 돌아가고 muwi가 만든 복제본을 지웁니다. 복제본을 손으로 고쳤으면 지우지 않습니다 |

자세한 내용은 [설치와 설정](setup.md#herdr-앱-화면)에 있습니다.

## 설치와 설정

| 명령 | 설명 |
| --- | --- |
| `muwi setup` | 터미널용 `muwi` 명령과, 붙어 있는 터미널 연결과 보기(Herdr 앱의 그래프 칸 등)를 설치합니다. 전에 커넥터를 넣은 도구는 새 버전에 맞춥니다 |
| `muwi setup --tools` | 아는 AI 도구와, 이 컴퓨터에 깔렸는지, 커넥터를 넣었는지 보여 줍니다 |
| `muwi setup --tool <도구>[,<도구>]` | 그 AI 도구에 커넥터(지침, 사용법 skill, 훅 또는 그 도구의 플러그인 파일)를 넣습니다 |
| `muwi setup --all` | 깔려 있는 AI 도구 전부에 커넥터를 넣습니다 |
| `muwi setup --remove` | `muwi setup`으로 설치한 것을 지웁니다. 보기가 바꾼 것(`muwi layout`으로 바꾼 화면 등)도 그 보기가 되돌립니다 |
| `muwi config` | 현재 설정을 보여 줍니다. 설정은 보기가 정합니다 (보기 없이 쓰면 설정이 없습니다) |
| `muwi config layout on\|off` | (`@muwi/herdr-app`) 화면에 muwi 칸이 없을 때 `muwi layout`을 권하는 안내를 켜거나 끕니다. 기본값은 `on`입니다 |
| `muwi update [--check]` | npm에 나온 최신판으로 올리고, 전에 setup을 했으면 새 판으로 setup을 다시 해서 훅·그래프 칸·커넥터를 맞춥니다. 지금 `muwi`가 깔린 자리에 같은 Node의 npm으로 받습니다. `--check`는 새 판이 있는지만 봅니다. [업데이트하기](setup.md#업데이트하기) |

각 항목이 무엇을 설치하고 설정하는지는 [설치와 설정](setup.md)에 있습니다.

## 계획 적기

| 명령 | 설명 |
| --- | --- |
| `muwi plan --work <이름> --request "<시킨 말>" '<계획 JSON>'` | 새 작업의 계획을 적습니다 |
| `muwi plan --why "<이유>" '<계획 JSON>'` | 계획 전체를 바꿉니다. id가 같은 노드는 상태와 회차를 잇습니다 |

| 옵션 | 설명 |
| --- | --- |
| `--work <이름>` | 작업 이름. 새 작업이면 필수입니다 |
| `--request "<글>"` | 사용자가 시킨 말. 그래프의 "시킨 말"에 나옵니다 |
| `--title "<글>"` | 작업 제목. 계획 JSON의 `title`보다 우선합니다 |
| `--why "<이유>"` | 계획을 바꾸는 이유. 노드가 달라지면 필수입니다 |
| `--human` | 사용자가 시킨 변경으로 기록합니다 |
| `--file <경로>` | 계획 JSON을 파일에서 읽습니다. 표준 입력으로도 줄 수 있습니다 |
| `--json` | 결과를 JSON으로 출력합니다 |

계획 전체를 바꿀 때, 이미 시작했거나 끝난 노드가 새 계획에 없으면 명령이 실패합니다. 그 노드를 빼려면 `muwi remove`를 쓰세요.

### 계획 JSON

```json
{
  "title": "상품 목록에서 상품명을 누르면 상세로 이동",
  "nodes": [
    { "id": "read", "title": "티켓 읽기" },
    { "id": "impl", "title": "구현", "after": ["read"], "run": "session", "show": "pane" },
    { "id": "review", "title": "리뷰", "after": ["impl"], "run": "subagent" }
  ]
}
```

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `title` | 아니요 | 작업을 한 줄로 설명합니다 |
| `nodes` | 예 | 노드 목록. 1개 이상 60개 이하입니다 |
| `nodes[].id` | 예 | 노드 id. 한글, 영문, 숫자, `_`, `.`, `-`를 쓰고 계획 안에서 겹치지 않아야 합니다 |
| `nodes[].title` | 예 | 그래프의 카드에 나오는 제목입니다 |
| `nodes[].after` | 아니요 | 먼저 하는 노드의 id 목록. 그래프의 선이 됩니다. 순환하면 안 됩니다 |
| `nodes[].run` | 아니요 | 누가 할지: `me`(직접), `subagent`(서브에이전트), `session`(새 세션). AI가 정했을 때만 적습니다 |
| `nodes[].show` | 아니요 | 새 세션을 보여 줄 곳: `pane` 또는 `tab`. `run`이 `session`일 때만 적습니다 |

`after`가 같은 노드들은 그래프에서 나란히 그려집니다. `after`는 그림의 순서일 뿐입니다. 앞 노드가 끝나지 않아도 뒤 노드를 시작할 수 있습니다.

## 계획 바꾸기

하던 노드 앞에 끝나지 않은 노드를 넣으면(`muwi add --before`, 또는 계획을 다시 내서 앞 노드가 생기면) 하던 노드는 자동으로 잠시 멈춥니다. 그래프가 흐름대로 보이게 하려는 것입니다. 다시 하려면 `muwi node <id> start`를 실행하세요. 같은 회차로 이어집니다.


| 명령 | 설명 |
| --- | --- |
| `muwi add <id> "<제목>" --why "<이유>"` | 노드 하나를 넣습니다 |
| `muwi remove <id> --why "<이유>"` | 노드 하나를 뺍니다. 다음 노드는 뺀 노드의 앞 노드에 이어집니다 |

| `muwi add` 옵션 | 설명 |
| --- | --- |
| `--after <id,id>` | 이 노드들 뒤에 넣습니다 |
| `--before <id>` | 이 노드 앞에 넣습니다. `--after`와 함께 쓰면 두 노드 사이에 들어갑니다 |
| `--run me\|subagent\|session` | 누가 할지 적습니다 |
| `--show pane\|tab` | 새 세션을 보여 줄 곳을 적습니다 |
| `--human` | 사용자가 시킨 변경으로 기록합니다 |
| `--alone` | 어느 노드와도 잇지 않습니다 |

자리(`--after`, `--before`)를 주지 않으면 진행된 끝 뒤에 넣습니다. 진행된 끝은 끝났거나 하고 있는 노드 가운데 그 뒤로 끝났거나 하고 있는 노드가 없는 노드입니다. 시작 전, 응답 대기, 막힘, 잠시 멈춘 노드는 건너뜁니다. 그런 노드 뒤에 넣으면 그 뒤로 한 일이 모두 손대지 않은 노드 밑에 그려지기 때문입니다. 끝났거나 하고 있는 노드가 없으면 응답 대기·막힘 노드 가운데 맨 뒤 노드 뒤에, 그것도 없으면(계획만 적었으면) 맨 끝 노드(뒤에 아무것도 없는 노드) 뒤에 넣습니다. 그래프가 그리는 규칙([그리는 순서](graph.md#그리는-순서))과 같습니다. 어디에 넣었는지는 명령 출력에 나옵니다.

뺀 노드의 기록은 지워지지 않습니다. `muwi show`의 "빠진 노드"에 나옵니다.

## 진행 적기

| 명령 | 설명 |
| --- | --- |
| `muwi node <id> start` | 노드를 시작합니다. 끝냈거나 막혔던 노드면 다음 회차가 됩니다. 앞 노드가 아직 끝나지 않았으면 막지 않고, 같이 하는 거면 계획에서 나란히 두는 법(바꿀 `after`)과 순서대로 하려면 멈추는 법을 출력합니다 |
| `muwi node <id> start --sub` | 서브에이전트가 맡은 노드를 시작할 때 붙입니다. 그 노드가 서브에이전트가 한 것으로 적히고, `--work`를 붙여도 맡긴 세션이 붙어 있는 작업은 바뀌지 않습니다. 어느 AI 도구에서나 됩니다 |
| `muwi node <id> done ["<결과 한 줄>"]` | 노드를 끝냅니다 |
| `muwi node <id> wait "<물어볼 것>"` | 사용자의 결정을 기다립니다 |
| `muwi node <id> block "<이유>"` | 스스로 풀 수 없어서 멈춥니다 |
| `muwi node <id> pause` | 하던 노드를 잠시 멈춥니다. 다른 노드를 먼저 할 때 씁니다. 다시 `start`하면 같은 회차로 이어집니다 (`todo`도 같습니다) |
| `muwi flag [<id>] "<메모>"` | 문제 지점을 표시합니다. id를 생략하면 작업에 표시합니다 |

결과 한 줄은 `--result "<글>"`로도 줄 수 있습니다.

`start`를 기다리던 노드, 잠시 멈춘 노드, 다른 세션이 하던 노드에 실행하면 같은 회차로 이어집니다.

## 새 세션에 맡기기

터미널 연결(예: `@muwi/herdr`)이 붙어 있고, 멀티플렉서의 터미널 안에서 실행할 때 동작합니다. 터미널을 띄우고, 글을 보내고, 화면을 읽고, 닫는 일은 터미널 연결이 그 멀티플렉서로 합니다. 무엇을 띄우고 무엇을 적을지는 코어가 정합니다.

| 명령 | 설명 |
| --- | --- |
| `muwi run <id> "<맡길 일>"` | 노드를 맡을 세션을 띄웁니다. 그 세션은 시작하면서 그 노드에 붙습니다 |
| `muwi wait [<id>…] [--timeout <초>]` | 맡긴 노드가 끝나거나, 사용자를 기다리거나, 막히거나, 그 세션이 멈추거나 닫힐 때까지 기다립니다. 새로 띄운 세션이 아직 노드에 붙지 않았으면 앞 세션의 상태로는 돌아오지 않습니다. 세션이 멈췄거나 닫혔다는 것은 두 번 잇달아 보였을 때 알립니다. 노드를 주지 않으면 이 작업에서 새 세션에 맡긴 노드 중 끝나지 않은 것을 기다립니다. 기본 600초가 지나면 아직이라고 알리고 끝납니다 |
| `muwi peek <id> [--all]` | 그 노드를 맡은 세션의 화면을 봅니다. 기본은 마지막 80줄입니다 |
| `muwi tell "<말>"` | (맡은 세션에서) 맡긴 세션의 터미널에 알립니다. 끝났거나 막혔을 때 씁니다 |
| `muwi tell <id> "<말>"` | 그 노드를 맡은 세션에 말을 보냅니다 |
| `muwi tidy [<작업>]` | 끝난 노드를 맡았던 세션의 터미널을 닫습니다. 그 터미널을 지금 다른 대화가 쓰고 있거나 에이전트가 돌지 않으면 닫지 않습니다 |
| `muwi resume <id> [--new]` | 세션이 닫혀 멈춘 노드를 이어 합니다. 하던 대화를 다시 열 수 있으면 그 대화를 열고, 없거나 `--new`를 붙이면 새 대화를 띄워 그 노드를 맡깁니다. 그 노드를 하던 세션이 아직 살아 있으면 띄우지 않습니다 (`--force`로 띄웁니다). `--show`, `--down`, `--name`도 받습니다 |

| `muwi run` 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--show pane\|tab` | 계획의 `show`, 없으면 놓지 않음 | `pane`은 현재 터미널 옆에, `tab`은 새 tab에 놓습니다 |
| `--down` | 끔 | pane을 옆 대신 아래에 놓습니다 |
| `--cwd <폴더>` | 현재 폴더 | 그 세션이 일할 폴더입니다 |
| `--agent <도구>` 또는 `"<명령>"` | 맡기는 세션과 같은 도구 | 다른 도구에 맡기려면 도구 이름을 줍니다 (`--agent codex`). 명령을 직접 줄 수도 있습니다. 예: `"claude --model sonnet"`. 명령에 모델(`--model`, `-m`)을 주면 그 세션의 모델로 적어 둡니다. 훅이 모델을 알려 주지 않는 도구에서도 노드에 모델이 남습니다 |
| `--name <이름>` | 노드 id | 멀티플렉서의 목록에 나오는 이름입니다. 멀티플렉서에 맞게 바뀔 수 있습니다 |

`--agent`의 값은 공백으로 나눕니다. 따옴표로 묶은 인자나 공백이 든 경로는 쓸 수 없습니다.

띄운 세션은 환경 변수 `MUWI_RUN`, `MUWI_RUN_WORK`, `MUWI_RUN_NODE`(명령에 모델을 줬으면 `MUWI_RUN_MODEL`도)로 맡은 작업과 노드를 받습니다. 환경 변수를 넘기지 못하는 연결을 위해 기록 폴더의 `.spawns/<터미널>.json`에도 남기고, 맡은 세션이 붙으면 지웁니다.

## 환경 변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `MUWI_DIR` | `~/.muwi` | 기록 폴더입니다 |
| `MUWI_WORK` | 없음 | 명령이 다룰 작업 이름입니다. `--work`와 같습니다 |
| `MUWI_SESSION` | 그 도구의 세션 id (없으면 터미널) | 세션 이름을 직접 정합니다 |
| `MUWI_TERMINALS` | `muwi setup`이 적어 둔 연결 | 터미널 연결 모듈의 경로. `@muwi/herdr`와 `@muwi/herdr-app`의 `muwi` 명령이 Herdr 연결로 정합니다 |
| `MUWI_VIEWS` | `muwi setup`이 적어 둔 보기 | 보기 모듈의 경로들 (경로 구분자로 잇습니다). `@muwi/herdr-app`의 `muwi` 명령이 Herdr 앱 보기로 정합니다 |
| `MUWI_WAIT_POLL_MS` | `2000` | `muwi wait`가 기록을 다시 읽는 간격 (ms) |
| `MUWI_NO_UPDATE_CHECK` | 없음 | `1`이면 새 버전 알림(대화 자리, 그래프 칸, 터미널)을 끕니다. [업데이트하기](setup.md#업데이트하기) |

## 내부 명령

`muwi board [--work <작업>…] [--down] [--fit WxH]`와 `muwi hook`은 보기와 훅이 쓰는 명령입니다. 직접 쓸 일이 없습니다. `muwi board`는 보기가 읽는 기록(작업 목록, 고른 작업의 노드와 그래프 좌표, 이어 하기에 쓸 사실, 최근 세션)을 JSON 한 벌로 냅니다. `--work`를 여러 번 주면 그 작업들의 그래프를 모두 `graphs`로 줍니다 (첫 작업이 고른 작업. 그래프 칸이 여러 작업을 나눠 그릴 때 씁니다). 터미널마다 지금 그 터미널을 쓰는 세션(`owners`)도 줍니다. 모양이 바뀌면 `version`이 올라갑니다. 기록은 바꾸지 않고, 휴지통에서 30일 지난 작업만 비웁니다.
