# 원리

**AI가 일하면서 "지금 뭘 하고 있는지"를 파일에 적고, 그래프 칸이 그 파일을 읽어 그림으로 보여 줍니다.**

| 필요한 것 | 방법 |
| --- | --- |
| AI가 파일에 적는 방법 | `muwi` 명령. AI가 터미널에서 실행하면 기록 파일이 써집니다 |
| AI가 적게 만드는 방법 | 세션이 시작될 때 훅이 넣어 주는 지침 몇 줄. 지침을 놓쳐도, 계획 없이 파일을 고치려 하면 훅이 알려 줍니다 |
| 그림으로 보여 주는 방법 | Herdr 앱의 그래프 칸이 기록을 읽어 그립니다. 기록이 바뀌면 전체를 다시 그립니다 (배치는 elkjs) |
| 읽은 skill, 서브에이전트 기록 | AI가 적지 않습니다. 일어나는 순간 훅이 한 줄을 남기고, 그때 하고 있던 노드를 같이 적습니다 |
| 새 세션 띄우기 | AI가 `muwi run`을 실행하면 muwi가 Herdr에 세션을 띄웁니다. 띄울지, 어디에 놓을지는 AI가 정합니다 |

## 한 번 따라가 보기

```
나: PROJ-123 작업해줘                       ← 명령을 붙이지 않고 그냥 시킨다

① AI가 실행:  muwi plan --work shop-web-PROJ-123 --request "…" '{"nodes":[…]}'
   → ~/.muwi/shop-web-PROJ-123/plan.json 이 생기고, 그래프 칸에 카드들이 그려진다
② AI가 실행:  muwi node read start
   → [티켓·기획 읽기] 카드가 "작업 중"으로 바뀐다
   → 계획 파일의 그 노드에 "지금 하고 있는 쪽: 이 세션, 1회차"가 적힌다
③ AI가 기획서 읽는 skill을 읽는다
   → (자동) 훅이 계획 파일에서 "이 세션이 지금 read를 하는 중"임을 보고,
     events.jsonl에 "skill 읽음 · read 1회차" 한 줄을 남긴다
④ AI가 실행:  muwi node read done "요구사항 2건"
   → 카드가 "끝"으로 바뀐다. "지금 하고 있는 쪽"이 지워진다
⑤ 계획이 바뀌면 AI가 실행:  muwi add nourl "URL 없는 행 처리" --after impl --before check --why "…"
   → 그래프가 다시 그려지고, 바뀐 이유가 기록에 남는다
⑥ AI가 구현을 새 세션에 맡기기로 하면 실행:  muwi run impl "목록 화면에 링크 추가…" --show pane
   → Herdr의 오른쪽 pane에 Claude 세션이 뜬다 (키보드는 있던 칸에 그대로)
   → (자동) 그 세션이 시작되면서 이 작업의 impl 노드에 붙는다. 카드: "작업 중", 표시 "세션"
   → 그 세션이 끝나면 직접 muwi node impl done "커밋 2개"를 적고 맡긴 세션에 알린다
⑦ AI가 리뷰를 서브에이전트에 맡기면
   → (자동) 훅이 서브에이전트가 뜬 것과 읽은 skill을 리뷰 노드에 적는다. 카드 표시 "서브"
⑧ 리뷰에서 걸려서 AI가 다시 실행:  muwi node impl start
   → 같은 카드에 "2회차"가 붙는다. 1회차의 기록은 그대로 남는다
⑨ 내 결정이 필요하면 AI가 실행:  muwi node pr wait "PR 올릴까요?"
   → 카드가 "나를 기다림"으로 바뀌고, 작업 목록 맨 위로 올라온다
```

## 적는 순간에 노드를 같이 적는다

기록 파일에는 두 종류의 줄이 있습니다. AI가 `muwi` 명령으로 적는 줄(노드 시작과 끝)과 훅이 보고 적는 줄(skill을 읽음, 서브에이전트가 뜸)입니다.

훅이 적는 줄에는 **어느 노드의 몇 번째 회차인지**가 같이 들어갑니다. 훅이 적는 그 순간에 계획 파일을 보고, 그 세션(또는 그 서브에이전트)이 "지금 하고 있는 노드"를 읽어서 적습니다.

```
AI가 적는 줄    10:00 [브랜치 준비] 시작 · 1회차 · 시작한 쪽: 이 세션
훅이 적는 줄         10:02 skill branch-rule 읽음 → [브랜치 준비] 1회차
                     10:03 서브에이전트가 뜸       → [브랜치 준비] 1회차
```

그래프를 그릴 때는 적힌 대로 모으기만 합니다. 시각을 맞춰 보며 "이 시간에는 이 노드를 하고 있었겠지" 하고 짐작하지 않습니다. 그래서 이런 경우에도 기록이 섞이지 않습니다.

- 같은 노드를 다시 해도 회차마다 따로 남습니다.
- 세션이 직접 하는 노드에서 서브에이전트가 잠깐 떠도 노드의 주인이 바뀌지 않습니다.
- 다른 세션이 넘겨받아도, 넘겨준 세션이 읽은 skill이 붙지 않습니다.

확실하지 않은 것은 그렇게 표시합니다.

| 표시 | 뜻 |
| --- | --- |
| 확실하지 않음 | 읽을 때 같은 쪽이 노드 여러 개를 동시에 하고 있었습니다. 가장 늦게 시작한 노드에 적었습니다 |
| 기록 없음 (시작과 끝을 한꺼번에 적음) | 일을 다 하고 `start`와 `done`을 연달아 적었습니다. 하는 동안 읽은 skill은 노드 밖에 적혀 있습니다 |
| 볼 수 없었음 | 그 세션에서 훅이 돌지 않았습니다. 읽지 않은 것이 아니라 알 수 없는 것입니다 |

## muwi가 요구하는 것 하나

`muwi`는 적어 두고, 시키면 세션을 띄워 줄 뿐입니다. 앞 노드가 끝나지 않아도 다음 노드를 시작할 수 있고, 결과 형식도 검사하지 않습니다.

요구하는 것은 하나뿐입니다. **파일을 고치기 전에 계획을 적거나, 계획 없이 진행한다고 밝히는 것**(`muwi skip "<이유>"`). 둘 다 하지 않고 파일을 고치려 하면 훅이 수정을 돌려보내고 방법을 알려 줍니다. 지침만으로는 계획을 적지 않는 때가 있어서 넣었습니다.

이 확인은 **사람이 새로 일을 시킬 때마다** 다시 합니다.

| 그 대화의 상태 | 새로 시킨 뒤 처음 파일을 고칠 때 |
| --- | --- |
| 하던 작업에 끝나지 않은 노드가 있다 | 통과합니다. 그 작업을 계속하는 것으로 봅니다 |
| 하던 작업의 노드가 다 끝났다 | 다시 묻습니다. 그 작업에 노드를 넣거나, 새 계획을 적거나, skip |
| 앞에서 skip만 했다 | 다시 묻습니다. skip은 그 요청에만 적용됩니다 |

기록 폴더, 에이전트 설정, 임시 폴더에 쓰는 파일은 해당하지 않습니다. 끄려면 `muwi config nudge off`입니다.

## 훅이 하는 일

플러그인이 Claude Code에 훅을 겁니다. 모두 `hooks/hook.sh`를 거쳐 `muwi hook`으로 들어갑니다.

| 언제 | 하는 일 |
| --- | --- |
| 세션이 시작될 때 | 지침(`hooks/instructions.md`)을 세션에 넣습니다. Herdr 터미널에 지금 도는 세션의 이름을 라벨로 붙입니다. `muwi run`으로 뜬 세션이면 맡은 노드에 붙이고 시작을 적습니다 |
| 사람이 말을 걸 때 | 계획을 적었는지 다음 수정 때 다시 따지게 합니다 |
| 서브에이전트가 시작하고 끝날 때 | 어느 세션의 어떤 서브에이전트인지, 뜰 때 그 세션이 하고 있던 노드와 함께 적습니다 |
| skill을 읽은 뒤 | 누가(세션, 또는 어느 서브에이전트가) 어떤 skill을 읽었는지, 그때 하고 있던 노드와 함께 적습니다 |
| 파일을 고치기 전 | 계획도 `skip`도 없으면 수정을 돌려보냅니다 |
| 명령을 실행하기 전 | 서브에이전트가 `muwi node <id> start`를 실행하면 그 서브에이전트가 시작한 것으로 적히게 합니다. `guard`가 켜져 있으면 `git push`, `gh pr`, Bitbucket PR 쓰기 앞에서 사람에게 묻습니다 (기본 꺼짐) |

## 누가 했는지

계획에 적은 것(`run`)은 AI의 생각이고, 그래프의 표시는 기록에 적힌 사실입니다. 둘이 다르면 "계획과 다름"으로 보입니다.

회차의 주인은 **그 회차를 시작한 쪽**입니다.

| 누가 | 기록에 어떻게 남나 |
| --- | --- |
| 대화가 직접 | 노드 시작 줄에 그 세션이 적힙니다. 다음 날 새 대화가 이어서 해도, `/clear` 뒤에 해도 "직접"입니다 |
| 새 세션 | `muwi run`은 띄운 터미널에 작업 이름과 노드 id를 라벨로 붙입니다. 그 세션의 시작 훅이 라벨을 읽어 그 노드에 붙고, 붙었다는 줄을 남깁니다. 그 터미널에서 나중에 시작한 다른 대화는 다시 붙이지 않습니다 |
| 서브에이전트 | 서브에이전트는 세션 id가 띄운 세션과 같아서 명령만으로는 구분되지 않습니다. Claude Code가 훅에 넘겨주는 서브에이전트 id로 구분합니다. 서브에이전트가 `muwi node <id> start`를 실행하면 노드 시작 줄에 그 id가 적힙니다 |

세션이 노드를 시작해 두고 서브에이전트를 띄운 경우는 이렇게 봅니다.

- 계획에 서브에이전트로 하기로 적어 둔 노드면 서브에이전트가 한 것으로 봅니다.
- 그 밖에는 세션이 직접 한 것이고, 서브에이전트는 "도움"으로 따로 남습니다.

## 세션이 닫혔는지

muwi는 AI가 적어 준 것만 압니다. 세션을 닫아 버리면 "끝"을 적을 쪽이 없습니다. 그래서 보여 줄 때 Herdr에 물어봅니다(`hc ls`, `hc get`).

| Herdr의 답 | muwi의 판단 |
| --- | --- |
| 그 터미널이 없다 | 닫혔다 |
| 터미널은 있는데 에이전트가 돌지 않는다 (셸만 남았다) | 닫혔다 |
| 터미널에 붙은 세션 이름이 다르다 (같은 칸에서 다른 대화가 시작됐다) | 닫혔다 |
| 그 세션의 터미널을 모른다, 또는 Herdr 밖이다 | 판단하지 않는다 (살아 있는 것으로 둔다) |

닫힌 세션이 하던 노드는 "세션이 닫힘"으로 표시하고, 걸린 시간은 그 세션이 마지막으로 무언가를 적은 때까지만 셉니다. 기록 파일은 고치지 않습니다. 보여 줄 때마다 다시 물어봅니다.

## 읽은 skill

노드마다 "쓸 skill"을 미리 적지 않습니다. 실제로 읽은 것만 훅이 남깁니다. 같은 skill을 여러 노드에서 읽어도, 한 노드에서 여러 번 읽어도 그대로 기록됩니다.

| 표시 | 뜻 |
| --- | --- |
| 읽음 | 이 회차를 하는 동안 읽었다 |
| 이미 읽은 상태 | 이 회차를 한 세션이 그 전에 읽어서 내용을 갖고 있다. 다시 부르지 않은 게 정상이다 |
| 서브에이전트가 읽음 | 서브에이전트만 읽었다. 내용은 서브에이전트가 끝나면 세션에 남지 않는다 |
| 없음 | 훅이 보고 있었는데 읽지 않았다 |
| 볼 수 없었음 | 그 세션에서 훅이 돌지 않았다 |

서브에이전트와 새 세션은 빈 상태에서 시작합니다. 그래서 서브에이전트가 한 회차에는 "이미 읽은 상태"를 붙이지 않고, 서브에이전트가 읽은 skill을 세션의 "이미 읽은 상태"로 넘기지도 않습니다.

기록되는 것은 AI가 Skill 도구로 부른 것과 `SKILL.md` 파일을 읽은 것입니다. skill을 읽고도 무시했는지, 읽지 않았지만 맞게 했는지는 기록으로 알 수 없어서 결과물을 봐야 합니다.

## 기록 파일

작업마다 폴더 하나(`~/.muwi/<작업>/`, `$MUWI_DIR`로 바꿀 수 있음)에 두 파일을 둡니다. 작업 이름은 `<저장소>-<작업키>`로 짓습니다.

- `plan.json`: 지금의 계획. 노드(`id`, `title`, `after`, `status`, 마지막 한 줄 `note`, AI가 정했으면 `run`과 `show`, 몇 번째 회차인지 `attempt`, 작업 중이면 지금 하고 있는 쪽 `by`), 시킨 말, 시작한 폴더, 형식의 판(`schema`).
- `events.jsonl`: 일어난 일을 한 줄씩. 노드 시작·끝(회차, 시작한 쪽), 계획 변경과 이유(빠진 노드가 무엇이었는지 포함), 읽은 skill, 서브에이전트의 시작·끝, 새 세션을 띄운 것과 맡긴 말, 문제 표시.

노드 상태는 `todo`(아직), `doing`(작업 중), `waiting`(나를 기다림), `blocked`(막힘), `done`(끝)입니다. 다시 하는 일은 되돌아가는 선으로 그리지 않고, 같은 노드를 다시 시작해 회차로 남깁니다. 기다리다 이어 하는 것과, 하는 중에 다른 쪽이 넘겨받는 것은 같은 회차입니다.

계획에서 뺀 노드는 그래프에서 사라지지만 기록은 남습니다. `muwi show`의 "빠진 노드"에 무엇이었고 왜 뺐는지가 나옵니다.

세션마다 `~/.muwi/.sessions/<세션>.json`에 붙어 있는 작업, 읽은 skill, Herdr 터미널 주소, 훅이 이 세션을 본 적이 있는지를 적어 둡니다. `muwi` 명령은 환경 변수(`CLAUDE_CODE_SESSION_ID`)에서, 훅은 Claude Code가 넘겨주는 `session_id`에서 같은 세션 이름을 얻습니다.
