# 원리

**AI가 일하면서 "지금 뭘 하고 있는지"를 파일에 적고, 그래프 칸이 그 파일을 읽어 그림으로 보여 줍니다.**

| 필요한 것 | 방법 |
| --- | --- |
| AI가 파일에 적는 방법 | `muwi` 명령. AI가 터미널에서 실행하면 기록 파일이 써집니다 |
| AI가 적게 만드는 방법 | 세션이 시작될 때 훅이 넣어 주는 지침 몇 줄. 지침을 놓쳐도, 계획 없이 파일을 고치려 하면 훅이 알려 줍니다 |
| 그림으로 보여 주는 방법 | Herdr 앱의 그래프 칸이 기록을 읽어 그립니다. 기록이 바뀌면 전체를 다시 그립니다 (배치는 elkjs) |
| 읽은 skill 기록 | AI가 적지 않습니다. skill을 읽는 순간 훅이 한 줄을 남깁니다 |
| 누가 했는지 기록 | AI가 적지 않습니다. 서브에이전트의 시작·끝은 훅이 남기고, 새 세션은 뜰 때 훅이 맡은 노드에 붙입니다 |
| 새 세션 띄우기 | AI가 `muwi run`을 실행하면 muwi가 Herdr에 세션을 띄웁니다. 띄울지, 어디에 놓을지는 AI가 정합니다 |

## 한 번 따라가 보기

```
나: PROJ-123 작업해줘                       ← 명령을 붙이지 않고 그냥 시킨다

① AI가 실행:  muwi plan --work shop-web-PROJ-123 --request "…" '{"nodes":[…]}'
   → ~/.muwi/shop-web-PROJ-123/plan.json 이 생기고, 그래프 칸에 카드들이 그려진다
② AI가 실행:  muwi node read start
   → [티켓·기획 읽기] 카드가 "작업 중"으로 바뀐다
③ AI가 기획서 읽는 skill을 읽는다
   → (자동) 훅이 events.jsonl에 "skill 읽음" 한 줄을 남기고, 카드에 붙는다
④ AI가 실행:  muwi node read done "요구사항 2건"
   → 카드가 "끝"으로 바뀐다. 다음 노드로
⑤ 계획이 바뀌면 AI가 실행:  muwi add nourl "URL 없는 행 처리" --after impl --before check --why "…"
   → 그래프가 다시 그려지고, 바뀐 이유가 기록에 남는다
⑥ AI가 구현을 새 세션에 맡기기로 하면 실행:  muwi run impl "목록 화면에 링크 추가…" --show pane
   → Herdr의 오른쪽 pane에 Claude 세션이 뜬다 (내 키보드 포커스는 그대로)
   → (자동) 그 세션이 시작되면서 이 작업의 impl 노드에 붙는다. 카드: "작업 중", 표시 "세션"
   → 그 세션이 끝나면 직접 muwi node impl done "커밋 2개"를 적고 맡긴 세션에 알린다
⑦ AI가 리뷰를 서브에이전트에 맡기면
   → (자동) 훅이 서브에이전트의 시작·끝과 읽은 skill을 리뷰 노드에 붙인다. 카드 표시 "서브"
⑧ 내 결정이 필요하면 AI가 실행:  muwi node pr wait "PR 올릴까요?"
   → 카드가 "나를 기다림"으로 바뀌고, 작업 목록 맨 위로 올라온다
```

## muwi가 요구하는 것 하나

`muwi`는 적어 두기만 합니다. 앞 노드가 끝나지 않아도 다음 노드를 시작할 수 있고, 결과 형식도 검사하지 않습니다.

요구하는 것은 하나뿐입니다. **파일을 고치기 전에 계획을 적거나, 계획 없이 진행한다고 밝히는 것**(`muwi skip "<이유>"`). 둘 다 하지 않은 세션이 파일을 고치려 하면 훅이 수정을 돌려보내고 방법을 알려 줍니다. 지침만으로는 계획을 적지 않는 때가 있어서 넣었습니다. 기록 폴더, 에이전트 설정, 임시 폴더에 쓰는 파일은 해당하지 않습니다. 끄려면 `muwi config nudge off`입니다.

## 훅이 하는 일

플러그인이 Claude Code에 훅을 겁니다. 모두 `hooks/hook.sh`를 거쳐 `muwi hook`으로 들어갑니다.

| 언제 | 하는 일 |
| --- | --- |
| 세션이 시작될 때 | 지침(`hooks/instructions.md`)을 세션에 넣습니다. `muwi run`으로 뜬 세션이면 맡은 노드에 붙이고 시작을 적습니다 |
| 서브에이전트가 시작하고 끝날 때 | 어느 세션의 어떤 서브에이전트인지 한 줄 남깁니다 |
| skill을 읽은 뒤 | 어느 세션이(서브에이전트면 어느 서브에이전트가) 어떤 skill을 읽었는지 한 줄 남깁니다 |
| 파일을 고치기 전 | 계획도 `skip`도 없는 세션이면 수정을 돌려보냅니다 |
| 명령을 실행하기 전 | 서브에이전트가 `muwi node <id> start`를 실행하면 그 노드를 그 서브에이전트의 것으로 적습니다. `guard`가 켜져 있으면 `git push`, `gh pr`, Bitbucket PR 쓰기 앞에서 사람에게 묻습니다 (기본 꺼짐) |

## 누가 했는지는 이렇게 기록됩니다

계획에 적은 것(`run`)은 AI의 생각이고, 그래프의 표시는 기록에서 본 사실입니다. 둘이 다르면 "계획과 다름"으로 보입니다.

| 누가 | 기록에서 어떻게 알아내나 |
| --- | --- |
| 계획을 낸 세션 | 노드를 시작한 세션이 계획을 처음 적은 세션과 같습니다 |
| 새 세션 | 노드를 시작한 세션이 다릅니다. `muwi run`은 띄운 터미널에 작업 이름과 노드 id를 라벨로 붙여 두고, 그 세션의 시작 훅이 라벨을 읽어 그 노드에 붙습니다 |
| 서브에이전트 | 서브에이전트는 세션 id가 띄운 세션과 같아서 명령만으로는 구분되지 않습니다. Claude Code가 훅에 넘겨주는 서브에이전트 id로 구분합니다 |

서브에이전트가 어느 노드를 했는지는 이렇게 정합니다.

1. 서브에이전트가 `muwi node <id> start`를 직접 실행했으면 그 노드입니다.
2. 아니면 띄운 세션이 그때 하고 있던 노드입니다. 여러 개면 서브에이전트로 하기로 한 노드, 아직 서브에이전트가 붙지 않은 노드, 가장 늦게 시작한 노드 순으로 고릅니다. 이 경우는 짐작입니다.

## 읽은 skill은 이렇게 기록됩니다

노드마다 "쓸 skill"을 미리 적지 않습니다. 실제로 읽은 것만 훅이 사건으로 남기고, 화면은 "그 노드가 진행되던 시간에, 그 노드를 맡은 세션이 읽은 skill"을 카드에 붙입니다. 같은 skill을 여러 노드에서 읽어도, 한 노드에서 여러 번 읽어도 그대로 기록됩니다.

| 표시 | 뜻 |
| --- | --- |
| 읽음 | 이 노드를 하는 동안 읽었다 |
| 이미 읽은 상태 | 같은 세션이 그 전에 읽어서 내용을 갖고 있다. 다시 부르지 않은 게 정상이다 |
| 서브에이전트가 읽음 | 그 노드를 한 서브에이전트가 읽었다. 내용은 서브에이전트가 끝나면 맡긴 세션에 남지 않는다 |
| 표시 없음 | 이 세션은 그 skill을 읽은 적이 없다 |

서브에이전트와 새 세션은 빈 상태에서 시작합니다. 그래서 서브에이전트가 한 노드에는 "이미 읽은 상태"를 붙이지 않고, 서브에이전트가 읽은 skill을 맡긴 세션의 "이미 읽은 상태"로 넘기지도 않습니다.

skill을 읽고도 무시했는지, 읽지 않았지만 맞게 했는지는 기록으로 알 수 없어서 결과물을 봐야 합니다.

## 기록 파일

작업마다 폴더 하나(`~/.muwi/<작업>/`, `$MUWI_DIR`로 바꿀 수 있음)에 두 파일을 둡니다. 작업 이름은 `<저장소>-<작업키>`로 짓습니다.

- `plan.json`: 지금의 계획. 노드(`id`, `title`, `after`, `status`, 마지막 한 줄 `note`, AI가 정했으면 `run`과 `show`), 시킨 말, 시작한 폴더.
- `events.jsonl`: 일어난 일을 한 줄씩. 노드 시작·끝, 계획 변경과 이유, 읽은 skill, 서브에이전트의 시작·끝, 새 세션을 띄운 것, 문제 표시.

노드 상태는 `todo`(아직), `doing`(작업 중), `waiting`(나를 기다림), `blocked`(막힘), `done`(끝)입니다. 다시 하는 일은 되돌아가는 선으로 그리지 않고, 같은 노드를 다시 시작해 회차로 남깁니다.

세션마다 `~/.muwi/.sessions/<세션>.json`에 붙어 있는 작업, 읽은 skill, Herdr 터미널 주소를 적어 둡니다. `muwi` 명령은 환경 변수(`CLAUDE_CODE_SESSION_ID`)에서, 훅은 Claude Code가 넘겨주는 `session_id`에서 같은 세션 이름을 얻습니다. AI가 적은 "노드 시작"과 훅이 적은 "skill 읽음"을 이 이름으로 잇습니다.

기록 폴더의 `.node`에는 muwi를 실행했던 Node의 경로를 적어 둡니다. 셸 설정을 읽지 않는 곳(Herdr가 띄운 세션의 훅)에서는 낮은 버전의 Node가 잡힐 수 있어서, `bin/muwi`가 이 경로를 먼저 씁니다.
