# 정해 둔 순서로 진행시키기

특정 작업을 원하는 순서대로 진행시킵니다. AI에게 순서를 알려 주고, AI가 그 순서에서 벗어나면 기록에서 확인하는 방식입니다.

muwi는 순서를 강제하지 않습니다. 벗어나는 것을 막는 기능은 없습니다.

## 원하는 정도에 맞는 방법 고르기

| 원하는 것 | 방법 |
| --- | --- |
| 이번 한 번만 이 순서로 | 시킬 때 순서를 같이 말하세요 |
| 이런 작업에는 이 단계가 꼭 들어가야 함 | skill에 "계획에 꼭 넣을 노드"를 적으세요 |
| 이런 작업은 항상 정확히 이 계획으로 | 계획을 JSON 파일로 만들어 두세요 |

## 이번 한 번만 순서 정하기

일을 시키면서 순서를 말하세요.

```
PROJ-123 작업해줘. 요구사항 정리 → 구현 → lint → 화면 확인 → PR 순서로 해
```

AI가 그 순서로 계획을 적습니다.

## 꼭 들어가야 할 단계 적어 두기

그 작업을 다루는 skill에 적으세요. AI가 그 skill을 읽으면 계획에 그 단계를 넣습니다.

```markdown
## 계획에 꼭 넣을 노드

- 화면이 바뀌는 작업: 구현 뒤에 "화면 확인" 노드
- 모든 작업: PR 앞에 "lint와 타입 검사" 노드
```

순서 전체를 적지 말고 꼭 필요한 단계만 적으세요. 나머지는 AI가 그 일에 맞게 정합니다.

## 정확히 같은 계획으로 시작하기

1. 계획을 JSON 파일로 저장하세요.

   ```json
   {
     "title": "QA 수정",
     "nodes": [
       { "id": "repro", "title": "재현" },
       { "id": "cause", "title": "원인 분석", "after": ["repro"] },
       { "id": "fix", "title": "수정", "after": ["cause"] },
       { "id": "verify", "title": "재현 절차로 확인", "after": ["fix"] }
     ]
   }
   ```

2. skill이나 지침에 그 파일로 시작하라고 적으세요.

   ```
   QA 티켓은 muwi plan --file ~/plans/qa-fix.json 으로 계획을 시작한다
   ```

계획 JSON의 형식은 [명령어](../reference/commands.md#계획-json)에 있습니다.

## 순서에서 벗어났는지 확인하기

AI가 계획을 바꾸면 작업의 기록에 남습니다.

```
계획이 바뀐 기록
  11-22 10:40  AI  -verify  이유: 재현 절차가 없어 확인할 수 없음
```

그래프에서 카드를 고르지 않으면 오른쪽에 이 기록이 나옵니다. 터미널에서는 `muwi show <작업>`으로 봅니다.

## 알아 둘 점

- 순서를 자세히 정할수록 AI가 그 일에 맞게 판단할 여지가 줄어듭니다. 꼭 필요한 단계만 정해 두는 방법을 먼저 써 보세요.
- 순서를 정해 둔 skill이 설치돼 있으면 AI는 계획을 스스로 짜지 않고 그 순서를 따릅니다.
