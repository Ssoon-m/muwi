# 문제 해결하기

muwi가 기대대로 동작하지 않을 때 증상별로 원인과 해결 방법을 찾습니다.

먼저 설치 상태를 확인하세요.

```sh
muwi --version                    # 터미널용 명령이 있는지
claude plugin list | grep muwi    # 플러그인이 켜져 있는지
hc exec '$HOME/.local/bin/muwi --version'   # Herdr가 띄우는 세션에서도 실행되는지
```

## 그래프 칸에 "기록을 읽지 못했어요"가 나올 때

그래프 칸은 `~/.local/bin/muwi`를 실행해서 기록을 읽습니다. 이 파일이 없으면 읽지 못합니다.

Claude Code 세션에서 `muwi setup`을 실행하세요. AI에게 "muwi setup 실행해줘"라고 해도 됩니다.

## 그래프 칸이 화면에 보이지 않을 때

`muwi setup`은 그래프 칸을 설치만 하고 화면에는 넣지 않습니다. 화면에 넣으세요.

```sh
muwi layout --status   # 지금 화면에 muwi 칸이 있는지, 넣을 자리가 있는지
muwi layout            # 사이드바의 Agents 자리에 작업 목록, 터미널 아래에 그래프
```

Herdr 앱에서 레이아웃을 다른 것으로 바꿨으면(`ctrl-shift-l`) muwi 칸이 없는 화면일 수 있습니다. `muwi layout`을 다시 실행하면 지금 레이아웃을 복제해서 muwi 칸을 넣습니다. 화면을 바꾸지 않고 보려면 `muwi open`을 쓰세요.

## 그래프가 지금 보는 터미널의 작업으로 바뀌지 않을 때

그래프는 그 터미널의 세션이 적은 기록으로 작업을 찾습니다. 다음을 확인하세요.

- 그 세션이 계획 없이 일하는 중이면 바뀌지 않습니다. 그래프 위쪽에 "지금 칸의 세션은 계획 없이 진행 중이에요"가 나옵니다.
- muwi를 설치하기 전에 연 세션은 기록이 없을 수 있습니다. 세션을 새로 여세요.
- 그래프 칸이 `props.work`로 작업에 고정돼 있으면 따라가지 않습니다.

## 일을 시켰는데 그래프에 아무것도 생기지 않을 때

원인을 순서대로 확인하세요.

1. **플러그인을 설치한 뒤에 연 세션인지 확인하세요.** 플러그인은 새로 연 세션부터 적용됩니다.
2. **작은 일이면 계획이 없는 것이 정상입니다.** 질문, 조사, 오타처럼 한 곳만 고치는 일에는 AI가 계획을 만들지 않습니다. `muwi status`에 그 작업이 없으면 AI가 계획 없이 진행한 것입니다.
3. **계획 알림이 켜져 있는지 확인하세요.** `muwi config`에서 `nudge`가 `off`면 AI가 계획 없이 파일을 고쳐도 알리지 않습니다. `muwi config nudge on`으로 켜세요.
4. **Node 버전을 확인하세요.** 방법은 아래 절에 있습니다.

## Node 24 이상이 필요하다고 나올 때

muwi는 Node 24 이상에서 실행됩니다. Node가 낮으면 명령이 "Node 24 이상이 필요해요"라고 알리고, 세션이 시작될 때 AI에게도 알립니다.

muwi는 다음 순서로 Node 24 이상을 찾습니다.

1. PATH의 `node`
2. 캐시에 적어 둔 경로 (`~/.cache/muwi/node`)
3. 로그인 셸의 PATH. 찾으면 캐시에 적습니다
4. `muwi setup`을 실행한 Node (`~/.local/bin/muwi`로 실행할 때만)

Herdr가 띄우는 세션과 그래프 칸은 셸 설정(`~/.zshrc` 같은)을 읽지 않아서, nvm이나 mise로 고른 Node가 PATH에 없습니다. 그래서 muwi는 VS Code처럼 로그인 셸(`$SHELL -ilc`)을 한 번 띄워 터미널과 같은 PATH를 받아 옵니다. 셸 설정으로 PATH를 정하는 방법이면 무엇이든 찾습니다. 셸을 띄우는 데 1초쯤 걸리므로 찾은 경로는 캐시에 적어 두고 다음부터 씁니다. 셸 설정이 10초 안에 끝나지 않으면 기다리지 않습니다.

캐시는 다음 경우에 버립니다.

- 캐시한 Node가 없어지거나 24보다 낮아졌을 때
- `muwi setup`을 다시 실행했을 때

**Node 버전을 바꿨다면 `muwi setup`을 다시 실행하세요.** 예를 들어 `nvm alias default 26`으로 바꿔도 전에 쓰던 버전이 남아 있으면 muwi는 그 버전을 계속 씁니다.

셸에서도 Node를 찾지 못하면 그 사실을 캐시에 적고 1시간 동안 다시 묻지 않습니다. Node를 설치했다면 `muwi setup`을 다시 실행하세요.

Herdr가 띄우는 세션에서 동작하는지는 이렇게 확인하세요.

```sh
hc exec '$HOME/.local/bin/muwi --version'
```

## 읽은 skill을 볼 수 없었다고 나올 때

카드나 `muwi show`에 "읽은 skill을 볼 수 없었어요"가 나오면, 그 세션에서 훅이 한 번도 실행되지 않은 것입니다. skill을 읽지 않았다는 뜻이 아닙니다.

- 플러그인이 꺼져 있는지 확인하세요: `claude plugin list`
- 그 세션의 Node가 24 이상인지 확인하세요. 낮으면 훅이 조용히 건너뜁니다.
- Codex처럼 훅이 없는 도구로 한 일은 항상 이렇게 나옵니다.
- 훅에서 오류가 났다면 `~/.muwi/.hook-errors.log`에 남습니다.

## 새 세션이 떴는데 진행되지 않을 때

새 세션이 처음 보는 폴더에서 뜨면 폴더 신뢰 확인에서 멈춥니다. 카드에 "세션이 입력을 기다림"이 나옵니다.

그 세션의 칸으로 가서 확인을 누르세요. AI는 이 확인을 대신 누르지 않습니다.

## 카드가 "새 세션이 뜨는 중"에서 바뀌지 않을 때

새 세션은 시작될 때 훅이 맡은 노드에 붙입니다. 훅이 실행되지 않으면 붙지 않습니다.

1. 그 세션이 폴더 신뢰 확인에서 멈춰 있지 않은지 보세요.
2. `hc exec '$HOME/.local/bin/muwi --version'`이 버전을 출력하는지 확인하세요.
3. 그 세션에서 직접 붙일 수도 있습니다: `muwi node <노드 id> start --work <작업>`

## "어느 작업인지 알 수 없어요"가 나올 때

`muwi add`, `muwi node`처럼 기록하는 명령은 그 세션이 붙어 있는 작업에만 기록합니다. 붙어 있는 작업이 없으면 이 오류가 나옵니다.

`--work <작업 이름>`을 붙이세요. 작업 이름은 `muwi status`에서 볼 수 있습니다.

## 계획을 다시 낼 때 노드가 빠졌다고 나올 때

"이미 시작했거나 끝난 노드가 새 계획에 없어요"라는 오류입니다.

계획 전체를 다시 낼 때, 진행 중이거나 끝난 노드가 새 계획에 빠져 있으면 muwi가 받지 않습니다. 다른 세션이 넣은 노드일 수 있습니다.

- `muwi show <작업>`으로 지금 계획을 보고, 그 노드를 포함해서 다시 내세요.
- 그 노드를 빼려는 것이면 `muwi remove <노드 id> --why "<이유>"`를 쓰세요.

## 끝난 일인데 카드가 "세션이 닫힘"일 때

AI가 "끝"을 기록하기 전에 세션이 닫혔습니다. muwi는 일이 끝났는지 알 수 없어서 상태를 바꾸지 않습니다.

직접 끝으로 기록하세요.

```sh
muwi node <노드 id> done "<결과 한 줄>" --work <작업>
```

## 계획 없이 파일을 고쳤는데 알림이 뜨지 않을 때

계획 알림은 AI가 파일 수정 도구(Edit, Write)를 쓸 때만 동작합니다. 셸 명령(`sed -i`, 리다이렉션)으로 고치는 것은 잡지 못합니다.

기록 폴더(`~/.muwi`), 에이전트 설정 폴더(`~/.claude`, `~/.codex`), 임시 폴더(`/tmp`, `$TMPDIR`)에 쓰는 파일도 알리지 않습니다.

## 플러그인 업데이트 뒤 그래프 칸이 예전 모양일 때

플러그인이 업데이트되면 다음 세션이 시작될 때 터미널용 명령과 그래프 칸을 새 버전에 맞춥니다. Claude Code 세션을 한 번 새로 여세요.
