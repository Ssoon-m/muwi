# 문제 해결하기

muwi가 기대대로 동작하지 않을 때 증상별로 원인과 해결 방법을 찾습니다.

먼저 설치 상태를 확인하세요.

```sh
muwi --version                    # 명령이 있는지 (npm i -g herdr-muwi)
muwi setup --tools                # 쓰는 AI 도구에 커넥터를 넣었는지
hc exec '$HOME/.local/bin/muwi --version'   # Herdr가 띄우는 세션에서도 실행되는지
```

## 그래프 칸에 "기록을 읽지 못했어요"가 나올 때

그래프 칸은 `~/.local/bin/muwi`를 실행해서 기록을 읽습니다. 이 파일이 없으면 읽지 못합니다.

터미널에서 `muwi setup`을 실행하세요. AI에게 "muwi setup 실행해줘"라고 해도 됩니다.

칸에 "화면을 불러오지 못했어요: <경로>"가 같이 나오면, `muwi setup`이 적어 둔 Herdr 화면(herdr-muwi)이 그 자리에 없는 것입니다. herdr-muwi를 지웠거나 다른 자리(다른 Node 버전)에 다시 깔았을 때 그렇습니다. 지금 깔린 herdr-muwi의 `muwi`로 `muwi setup`을 다시 실행하면 새 자리를 적습니다 ([다른 자리에 새로 깔았을 때](../reference/setup.md#업데이트하기)). 세션이 시작될 때 같은 내용이 `~/.muwi/.hook-errors.log`에도 남습니다.

## 그래프 칸이 화면에 보이지 않을 때

`muwi setup`은 그래프 칸을 설치만 하고 화면에는 넣지 않습니다. 화면에 넣으세요.

```sh
muwi layout --status   # 지금 화면에 muwi 칸이 있는지, 넣을 자리가 있는지
muwi layout            # 사이드바의 Agents 자리에 작업 목록, 터미널 아래에 그래프
```

Herdr 앱에서 레이아웃을 다른 것으로 바꿨으면(`ctrl-shift-l`) muwi 칸이 없는 화면일 수 있습니다. `muwi layout`을 다시 실행하면 지금 레이아웃을 복제해서 muwi 칸을 넣습니다. 화면을 바꾸지 않고 보려면 `muwi open`을 쓰세요.

## 그래프가 지금 보는 터미널의 작업으로 바뀌지 않을 때

그래프는 그 터미널의 세션이 적은 기록으로 작업을 찾습니다. 다음을 확인하세요.

- 그 세션이 계획 없이 일하는 중이면 바뀌지 않습니다. 그래프 위쪽에 "지금 칸의 세션은 계획 없이 진행 중이에요"가 나옵니다.
- muwi를 설치하기 전에 연 세션은 기록이 없을 수 있습니다. 세션을 새로 여세요.
- 그래프 칸이 `props.work`로 작업에 고정돼 있으면 따라가지 않습니다.

## 일을 시켰는데 그래프에 아무것도 생기지 않을 때

원인을 순서대로 확인하세요.

1. **그 AI 도구에 커넥터를 넣었는지, 넣은 뒤에 연 세션인지 확인하세요.** `muwi setup --tools`에서 그 도구가 "커넥터 넣음"인지 봅니다. 훅은 새로 연 세션부터 돕니다.
2. **한 번에 끝나는 일이면 계획이 없는 것이 정상입니다.** 질문에 바로 답하기, 한두 곳만 보고 답하는 확인, 오타처럼 한 곳만 고치는 일에는 AI가 계획을 만들지 않습니다. PR 리뷰나 여러 곳을 살피는 조사처럼 여러 단계로 하는 일은 파일을 고치지 않아도 계획을 적습니다. 0.5.1 이하의 muwi는 파일을 고치는 일에만 계획을 적게 했습니다. 그 전에 연 세션이면 새로 여세요. `muwi status`에 그 작업이 없으면 AI가 계획 없이 진행한 것입니다. 진행 중인 세션에 "muwi로 계획 적어줘"라고 하면 바로 그래프에 나옵니다.
3. **여러 단계로 하는 일인데 계획을 적지 않았으면 "계획 적어 줘"라고 말하세요.** muwi는 계획이 없어도 막지 않습니다. 0.5.x에 있던 계획 알림은 0.6.0에서 뺐습니다.
4. **Node 버전을 확인하세요.** 방법은 아래 절에 있습니다.

## Node 24 이상이 필요하다고 나올 때

muwi는 Node 24 이상에서 실행됩니다. Node가 낮으면 명령이 "Node 24 이상이 필요해요"라고 알리고, 세션이 시작될 때 AI에게도 알립니다.

muwi는 다음 순서로 Node 24 이상을 찾습니다.

1. PATH의 `node`
2. 캐시에 적어 둔 경로 (`~/.cache/muwi/node`)
3. 로그인 셸의 PATH. 찾으면 캐시에 적습니다
4. `muwi setup`을 실행한 Node (`~/.local/bin/muwi`로 실행할 때만)

Herdr가 띄우는 세션과 그래프 칸은 셸 설정(`~/.zshrc` 같은)을 읽지 않아서, nvm이나 mise로 고른 Node가 PATH에 없습니다. 그래서 muwi는 VS Code처럼 로그인 셸(`$SHELL -ilc`)을 한 번 띄워 터미널과 같은 PATH를 받아 옵니다. 셸 설정으로 PATH를 정하는 방법이면 무엇이든 찾습니다. 셸을 띄우는 데 1초쯤 걸리므로 찾은 경로는 캐시에 적어 두고 다음부터 씁니다. 셸 설정이 10초 안에 끝나지 않으면 기다리지 않습니다.

캐시는 다음 경우에 버립니다.

- 캐시한 Node가 없어지거나 24보다 낮아졌을 때
- `muwi setup`을 다시 실행했을 때

**Node 버전을 바꿨다면 `muwi setup`을 다시 실행하세요.** 예를 들어 `nvm alias default 26`으로 바꿔도 전에 쓰던 버전이 남아 있으면 muwi는 그 버전을 계속 씁니다.

셸에서도 Node를 찾지 못하면 그 사실을 캐시에 적고 1시간 동안 다시 묻지 않습니다. Node를 설치했다면 `muwi setup`을 다시 실행하세요.

Herdr가 띄우는 세션에서 동작하는지는 이렇게 확인하세요.

```sh
hc exec '$HOME/.local/bin/muwi --version'
```

## 읽은 skill을 볼 수 없었다고 나올 때

카드나 `muwi show`에 "읽은 skill을 볼 수 없었어요"가 나오면, 그 세션에서 훅이 한 번도 실행되지 않은 것입니다. skill을 읽지 않았다는 뜻이 아닙니다.

- 커넥터를 넣기 전에 연 세션인지 확인하세요. 훅은 세션이 시작될 때 불러옵니다. 그 전에 연 세션은 `muwi` 명령으로 계획과 진행은 적지만 훅은 돌지 않습니다. 이런 세션이 계획을 적으면 `muwi plan`이 "이 세션에서는 muwi 훅이 돌지 않아요"라고 알립니다. 세션을 새로 여세요.
- 그 세션의 Node가 24 이상인지 확인하세요. 낮으면 훅이 조용히 건너뜁니다.
- 커넥터를 넣지 않은 도구로 한 일은 항상 이렇게 나옵니다. `muwi setup --tools`로 그 도구에 커넥터를 넣었는지 봅니다.
- 훅에서 오류가 났다면 `~/.muwi/.hook-errors.log`에 남습니다.

## 서브에이전트에게 맡겼는데 계획과 다르다고(`≠계획`) 나올 때

서브에이전트가 한 일인지는 훅이 보고 알아봅니다. 훅이 보고 있는 세션에서 `≠계획`이 나오면, 서브에이전트가 `muwi node <id> start`를 실행하지 않고 세션이 대신 기록했다는 뜻입니다. 서브에이전트에게 맡길 때 노드를 시작하고 끝내는 것도 서브에이전트가 하게 하세요. 방법은 [서브에이전트와 새 세션 다루기](delegation.md)에 있습니다.

훅이 돌지 않은 세션에서는 누가 했는지 알 수 없습니다. 이때는 `≠계획`을 띄우지 않고 "계획대로 했는지 확인하지 못했어요"라고 나옵니다.

## 새 세션이 떴는데 진행되지 않을 때

새 세션이 처음 보는 폴더에서 뜨면 폴더 신뢰 확인에서 멈춥니다. 카드에 "세션이 입력을 기다림"이 나옵니다.

그 세션의 칸으로 가서 확인을 누르세요. AI는 이 확인을 대신 누르지 않습니다.

## 카드가 "새 세션이 뜨는 중"에서 바뀌지 않을 때

새 세션은 시작될 때 훅이 맡은 노드에 붙입니다. 훅이 실행되지 않으면 붙지 않습니다.

1. 그 세션이 폴더 신뢰 확인에서 멈춰 있지 않은지 보세요.
2. `hc exec '$HOME/.local/bin/muwi --version'`이 버전을 출력하는지 확인하세요.
3. 그 세션에서 직접 붙일 수도 있습니다: `muwi node <노드 id> start --work <작업>`

맡긴 세션의 터미널을 닫았으면 카드가 "맡긴 세션이 닫힘"으로 바뀝니다. 노드 기록의 "이어서 하려면"에서 "새 대화로 이어 가기"를 누르면, 그 세션을 띄웠던 폴더에서 새 탭이 열리고 그 노드를 이어서 합니다.

## "어느 작업인지 알 수 없어요"가 나올 때

`muwi add`, `muwi node`처럼 기록하는 명령은 그 세션이 붙어 있는 작업에만 기록합니다. 붙어 있는 작업이 없으면 이 오류가 나옵니다.

`--work <작업 이름>`을 붙이세요. 작업 이름은 `muwi status`에서 볼 수 있습니다.

## 계획을 다시 낼 때 노드가 빠졌다고 나올 때

"이미 시작했거나 끝난 노드가 새 계획에 없어요"라는 오류입니다.

계획 전체를 다시 낼 때, 진행 중이거나 끝난 노드가 새 계획에 빠져 있으면 muwi가 받지 않습니다. 다른 세션이 넣은 노드일 수 있습니다.

- `muwi show <작업>`으로 지금 계획을 보고, 그 노드를 포함해서 다시 내세요.
- 그 노드를 빼려는 것이면 `muwi remove <노드 id> --why "<이유>"`를 쓰세요.

## 끝난 일인데 카드가 "세션이 닫힘"일 때

AI가 "끝"을 기록하기 전에 세션이 닫혔습니다. muwi는 일이 끝났는지 알 수 없어서 상태를 바꾸지 않습니다.

직접 끝으로 기록하세요.

```sh
muwi node <노드 id> done "<결과 한 줄>" --work <작업>
```

## 업데이트 뒤 그래프 칸이 예전 모양일 때

muwi를 업데이트하면 다음 세션이 시작될 때 터미널용 명령과 그래프 칸을 새 버전에 맞춥니다. AI 세션을 한 번 새로 열거나 `muwi setup`을 다시 실행하세요.

새 모양이었다가 갑자기 예전 모양(`위 · 아래 · 오른쪽` 버튼이나 기록 칸 너비 조절이 없는 모양)으로 돌아갔다면, 0.4.0이나 0.5.0 때 연 세션이 아직 남아 있는 것입니다. 그 세션은 시작될 때(대화 압축, `/clear` 포함) 설치를 자기 버전으로 되돌렸습니다. `muwi setup`을 다시 실행하세요. 0.5.5부터는 설치 기록을 새 파일(`~/.muwi/setup.json`)에 적어서 옛 세션이 되돌리지 못합니다.

## Windows에서 진행이 기록되지 않을 때

Claude Code는 Windows에서 훅을 Git Bash로 실행합니다. Git for Windows가 없거나 Claude Code가 찾지 못하면 훅이 돌지 않습니다. 작업은 막히지 않지만 노드의 기록에 "읽은 skill을 볼 수 없었어요"가 나옵니다.

1. [Git for Windows](https://git-scm.com/download/win)를 설치하세요.
2. 기본 위치가 아닌 곳에 설치했으면 환경 변수 `CLAUDE_CODE_GIT_BASH_PATH`에 `bash.exe`의 경로를 넣으세요.
3. Claude Code 세션을 새로 여세요.

## Windows의 PowerShell에서 muwi를 찾지 못할 때

`muwi setup`이 넣은 `muwi.cmd`는 `%USERPROFILE%\.local\bin`에 있습니다. 이 폴더를 사용자 PATH에 넣고 터미널을 다시 여세요.

```powershell
$p = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$p;$env:USERPROFILE\.local\bin", "User")
```
