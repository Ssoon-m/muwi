## 작업 진행 방식 (muwi)

여러 단계로 하는 일을 맡으면, 시작하기 전에 이번 일을 어떻게 진행할지 계획을 짜서 `muwi` 명령으로 적는다. 파일을 고치는지와는 상관없다. 기능 구현, 버그 수정, PR 리뷰, 여러 곳을 살피는 조사, 서브에이전트나 새 세션에 나눠 맡기는 일이 모두 여기에 든다. 사람은 이 기록을 그래프로 보면서 지금 무슨 일이 일어나는지 확인한다. 적지 않으면 사람에게는 아무것도 보이지 않는다. 순서와 방법은 정해져 있지 않다. 이번 작업에 맞게 직접 정한다.

- 시작할 때: 계획(노드와 순서)을 짜서 `muwi plan --work <이름> --request "<시킨 말>" '<계획 JSON>'`으로 적는다. 작은 작업이면 노드 두세 개로 충분하다. 노드는 하는 순서대로 `after`로 잇는다 (방향 있는 선으로 이어진 그래프). 동시에 해도 되는 노드는 같은 노드 뒤에 둔다.
- 진행하면서: 노드를 시작할 때 `muwi node <id> start`, 끝낼 때 `muwi node <id> done "<결과 한 줄>"`. 시작은 그 일을 하기 전에 적는다. 일을 다 하고 시작과 끝을 한꺼번에 적으면, 하는 동안 있었던 일이 그 노드에 남지 않는다.
- 노드를 누가 할지(직접, 서브에이전트, 새 세션)와 새 세션을 어디에 보여 줄지도 스스로 정한다. 정했으면 계획의 노드에 `run`과 `show`로 적는다. 새 세션은 `muwi run <id> "<맡길 일>"`로 띄운다. 터미널 연결이 없거나 멀티플렉서의 터미널 밖이면 `muwi run`이 그렇다고 알려 준다. 그때는 새 세션에 맡길 수 없다. 서브에이전트에 맡길 때는 그 서브에이전트가 `muwi node <id> start --sub --work <작업>`으로 시작하고 `muwi node <id> done "<결과>" --work <작업>`으로 끝내게 한다.
- 계획이 바뀌면: 바뀐 계획을 이유와 함께 다시 적는다 (`muwi add`, `muwi remove`, `muwi plan --why`). 사람이 바꾸라고 했으면 `--human`을 붙인다. 계획은 방향 있는 선으로 이어진 그래프다. 노드를 넣을 때는 어느 노드 다음인지 꼭 적는다 (`--after`, 하던 노드 앞이면 `--before`). 앞 노드를 고르지 못하는 일은 이 작업의 흐름에 없는 일이니 새 작업으로 적는다 (`--alone`으로 넣지 않는다).
- 계획과 다르게 진행하면(끝낸 노드를 다시 하기, 앞 노드가 끝나기 전에 시작, 계획과 다른 쪽이 하기) 판단의 근거를 `muwi node <id> start --why "<근거>"`로 남긴다. 한 일을 다시 말하지 말고 그렇게 판단한 근거를 적는다 ("직접 함"이 아니라 "바뀐 파일이 하나뿐이라").
- 하던 노드보다 먼저 할 일이 끼어들면: 그 일을 하던 노드 앞에 넣는다 (`muwi add <id> "<제목>" --before <하던 노드>`). 하던 노드는 자동으로 잠시 멈춘다. 다시 할 때 `muwi node <id> start` (같은 회차로 이어진다). 직접 멈추려면 `muwi node <id> pause`.
- 사람의 결정이 필요해 멈출 때: `muwi node <id> wait "<물어볼 것>"`으로 적고 묻는다. 적지 않으면 그래프에는 계속 작업 중으로 보인다.
- 계획을 만들지 않는 경우: 한 번에 끝나는 일. 질문에 바로 답하기, 한두 곳만 보고 답하는 확인, 오타처럼 한 곳만 고치는 일, 명령 하나 실행하기. 계획이 없어도 muwi는 막지 않는다. 작게 시작한 일이 여러 단계로 커지면 그때 계획을 적는다.
- 같은 대화에서 다른 일을 새로 시키면: 하던 작업에서 시킨 일을 이루는 일(리뷰 반영, 다시 확인, 빠뜨린 단계)이면 그 작업에 노드를 넣고(`muwi add --after`), 새로 시킨 일이면 같은 저장소·같은 주제여도 새 이름(`--work`)으로 계획을 적는다. 헷갈리면 새 작업이다. 하던 작업의 노드에 섞어 적지 않는다.
- 이어가는 요청("아까 그거")이면 `muwi status`로 기존 작업부터 찾는다.
- 다른 세션이 맡긴 노드를 하는 중이면 계획을 새로 만들지 않고, 맡은 노드의 시작과 끝만 적는다. 맡은 일을 쪼개야 하면 `muwi add <id> "<제목>" --after <앞 노드>`로 같은 계획에 노드를 넣는다.
- 계획 JSON의 모양, 서브에이전트와 새 세션에 맡기는 방법, 지난 작업의 문제를 진단하는 방법은 muwi skill에 있다. 이 세션에서 처음 계획을 적기 전에 한 번 읽는다. `muwi` 명령이 없으면 기록 없이 평소대로 진행한다.
