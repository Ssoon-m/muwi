# 작업 계획과 진행 기록

작업을 맡은 세션이 이번 작업을 어떻게 진행할지 스스로 정하고, 그 계획과 진행을 `muwi`로 적는다.
사람은 이 기록을 그래프(보기)나 `muwi show`로 보면서 지금 무슨 일이 일어나는지 확인하고, 결과가 이상하면 기록에서 원인을 찾는다.

`muwi`는 적어 두고, 시키면 세션을 띄워 줄 뿐이다. 순서를 막지 않고 다음 할 일을 정해 주지 않는다. 어떤 노드를 둘지, 어떤 skill을 쓸지, 노드를 직접 할지 서브에이전트나 새 세션에 맡길지, 새 세션을 어디에 띄울지는 전부 맡은 쪽이 판단한다.

## 계획 쓰기

여러 단계로 하는 일을 맡으면 시작하기 전에 계획을 적는다. 파일을 고치는지와는 상관없다. PR 리뷰나 여러 곳을 살피는 조사도 단계가 여럿이면 계획을 적는다. 한 번에 끝나는 일(질문에 바로 답하기, 한두 곳만 보고 답하는 확인, 오타처럼 한 곳만 고치는 일)에는 만들지 않는다.

계획을 적지 않아도 muwi는 막지 않는다. 적을지는 일의 크기를 보고 스스로 정한다. 작게 시작한 일이 여러 단계로 커지면 그때 계획을 적는다.

```sh
muwi plan --work shop-web-PROJ-123 --request "PROJ-123 작업해줘" '{
  "title": "상품 목록에서 상품명을 누르면 상세로 이동",
  "nodes": [
    { "id": "read",   "title": "티켓·기획 읽기" },
    { "id": "branch", "title": "브랜치 준비",    "after": ["read"] },
    { "id": "impl",   "title": "클릭 이동 구현", "after": ["branch"] },
    { "id": "check",  "title": "화면으로 확인",  "after": ["impl"] },
    { "id": "pr",     "title": "PR 올리기",      "after": ["check"] }
  ]
}'
```

- `--work`는 작업 이름이고 작업 폴더(`~/.muwi/<이름>/`)의 이름이 된다. `<저장소>-<작업키>`로 짓는다 (`shop-web-PROJ-123`, `shop-web-pr-58`). 작업키는 티켓 키, PR이면 `pr-<번호>`, 둘 다 없으면 짧은 영문 요약이다. 저장소를 아직 모르면 작업키만 쓴다.
- `--request`에는 사용자가 시킨 말을 그대로 넣는다.
- 노드는 **사람이 그래프에서 읽고 무슨 일인지 알 수 있는 덩어리**로 나눈다. 이번 작업에 실제로 필요한 것만 적는다. 작은 작업이면 두세 개로 충분하다.
- 노드는 하는 순서대로 `after`로 잇는다. `after`는 그 노드보다 먼저 하는 노드다. 동시에 해도 되는 노드는 같은 `after`를 주면 그래프에서 나란히 놓인다. 선 없이 늘어놓으면 그래프에 따로 떨어진 카드로 보이고 `muwi`가 알린다.
- 하기로 한 일은 노드로 드러낸다. 그래프에 없는 일은 사람에게 보이지 않는다.
- 누가 할지를 정했으면 노드에 `"run"`을 적는다 ([노드를 누가 하나](#노드를-누가-하나)). 정하지 않았으면 뺀다.
- 긴 JSON은 `--file <경로>`나 표준 입력(heredoc)으로 줘도 된다.

이어가는 요청("아까 그거 리뷰 달렸어")이면 새로 만들지 않고 `muwi status`로 기존 작업을 찾아 `--work <이름>`으로 이어 간다. 필요한 노드는 `muwi add <id> "<제목>" --after <앞 노드>`로 붙인다.

## 진행 적기

| 언제 | 명령 |
| --- | --- |
| 노드를 시작할 때 | `muwi node <id> start` |
| 노드를 끝낼 때 | `muwi node <id> done "<결과 한 줄>"` |
| 사람의 결정이 필요해 멈출 때 | `muwi node <id> wait "<물어볼 것>"` 그리고 사용자에게 묻는다 |
| 스스로 풀 수 없게 막혔을 때 | `muwi node <id> block "<이유>"` |

- 끝낸 노드를 다시 해야 하면(검증에서 걸려 다시 구현) 같은 노드를 다시 `start`한다. 2회차로 기록된다. 되돌아가는 선을 그리지 않는다. 그 사이에 이어진 노드(리뷰 반영 등)를 끝냈으면 그래프가 다시 한 회차를 그 뒤에 새 카드로 그린다.
- 결과 한 줄에는 다음 사람이 알아야 할 것을 적는다 ("요구사항 2건, 미정 1건", "커밋 a1b2c3d").
- 읽은 skill은 적지 않는다. 훅이 자동으로 기록한다.
- 사람의 답을 기다리는 동안에는 그 노드를 `wait`로 둔다. 적지 않고 묻기만 하면 그래프에는 계속 작업 중으로 보인다.

## 계획 바꾸기

진행하다 계획이 달라지면 바로 고쳐 적는다. 이유를 꼭 남긴다. 나중에 "왜 이렇게 됐지"를 볼 때 가장 먼저 읽는 줄이다.

```sh
muwi add nourl "URL 없는 행 처리" --after impl --before check --why "상세 URL이 없는 연수원이 있음"
muwi remove check --why "화면이 바뀌지 않는 변경이라 화면 확인이 필요 없음"
muwi plan --why "요구사항이 두 화면으로 늘어남" '<새 계획 JSON 전체>'   # 크게 바꿀 때. 같은 id의 노드는 상태를 잇는다
```

사용자가 바꾸라고 한 것이면 `--human`을 붙이고 그 말을 이유에 적는다 (`--why "화면 확인 전에 lint부터 돌리라고 함" --human`).

`muwi add`에는 어느 노드 다음인지(`--after`) 꼭 적는다. 하던 노드 앞에 끼우려면 `--before`, 이 작업 안의 일인데 순서와 상관없으면 `--alone` (새로 시킨 일을 넣는 데 쓰지 않는다). 앞 노드를 고르지 못하는 일은 이 작업의 흐름에 없는 일이다. 노드로 넣지 말고 새 작업으로 적는다 (자리 없이 넣으면 muwi가 그렇게 돌려보낸다).

## 노드를 누가 하나

노드마다 누가 할지는 맡은 쪽이 정한다. muwi에는 "이럴 때는 이것"이라는 기준이 없다. 정한 것과 실제로 한 것을 그래프에 보여 줄 뿐이다.

| 누가 | 계획에 적을 때 | 하는 법 |
| --- | --- | --- |
| 직접 | `"run": "me"` 또는 비워 둔다 | 계획을 낸 세션이 그대로 한다 |
| 서브에이전트 | `"run": "subagent"` | 그 도구의 서브에이전트 기능으로 띄운다 (예: Claude Code의 Agent 도구) |
| 새 세션 | `"run": "session"`, 보여 줄 곳을 정했으면 `"show": "pane"` 또는 `"tab"` | `muwi run <id> "<맡길 일>"`. 터미널 연결이 있고, 멀티플렉서의 터미널 안에서 돌 때만 된다 |

- `run`과 `show`는 정했을 때만 적는다. 도중에 생각이 바뀌면 계획을 고쳐 적는다 (`muwi plan --why`).
- 계획에 적은 것과 다르게 끝난 노드는 그래프에 "계획과 다름"으로 보인다. 막지는 않는다.

고르는 데 필요한 사실은 이렇다.

- **서브에이전트**는 빈 상태에서 시작한다. 이 대화도, 앞에서 읽은 skill도 모른다. 결과만 돌아오고, 끝나면 그 맥락은 사라진다. 사람에게는 진행이 보이지 않고 끼어들 수 없다.
- **새 세션**도 빈 상태에서 시작한다. 멀티플렉서에 터미널로 떠서 사람이 보고 끼어들 수 있고, 끝난 뒤에도 남아서 이어 시킬 수 있다. 맥락을 처음부터 읽으므로 토큰이 더 든다.
- 새 세션이 처음 보는 폴더에서 뜨면 폴더 신뢰 확인에서 멈춘다. 이건 사람이 답한다. 대신 눌러 주지 않는다. 권한 확인도 같다.

### 서브에이전트에 맡길 때

서브에이전트에게 작업 이름과 노드 id를 알려 주고, 그 서브에이전트가 아래 두 줄을 직접 적게 한다.

```sh
muwi node <id> start --sub --work <작업>     # 일을 하기 전에
muwi node <id> done "<결과 한 줄>" --work <작업>
```

`--sub`는 "이 노드는 서브에이전트가 한다"고 스스로 밝히는 것이다. 그래프에 서브에이전트가 한 노드로 나오고, 어떤 AI 도구에서든 된다. 서브에이전트를 알려 주는 도구(Claude Code, Codex 등)에서는 그 서브에이전트가 읽은 skill도 그 노드에 붙고, `--sub`를 빼먹어도 알아본다. 서브에이전트가 `--work`를 붙여 적어도 맡긴 세션이 붙어 있는 작업은 바뀌지 않는다.

직접 노드를 시작해 두고 서브에이전트를 띄워도 기록은 된다. 다만 여러 노드를 동시에 하고 있으면 어느 노드의 서브에이전트인지 짐작으로 붙는다.

### 새 세션에 맡길 때

터미널 연결이 있고 멀티플렉서의 터미널 안에서 돌 때만 된다. 아니면 `muwi run`이 그렇다고 알려 준다. 그때는 서브에이전트에 맡기거나 직접 한다.

```sh
muwi run impl "목록 화면에 상세 링크를 추가해줘. 범위는 src/product/list.tsx" --cwd ~/work/shop-web-PROJ-123 --show pane
```

- 그 세션은 뜨면서 이 작업의 그 노드에 붙고, 시작이 적힌다. 끝과 기다림은 그 세션이 적는다 (그 세션에 방법이 전달된다).
- `--show pane`은 이 터미널 옆(`--down`이면 아래)에, `--show tab`은 새 tab에 놓는다. 주지 않으면 계획의 `show`를 따르고, 그것도 없으면 놓지 않고 띄운다. 놓지 않아도 그래프에는 보인다. 사용자의 키보드 포커스는 옮기지 않는다.
- `--cwd`는 그 세션이 일할 폴더(worktree 등), `--agent`는 띄울 도구나 명령이다. 주지 않으면 지금 세션과 같은 도구로 띄운다. 다른 도구에 맡기려면 도구 이름을 준다 (`--agent codex`. 리뷰는 Codex, 구현은 Claude Code처럼 나눠도 같은 계획과 그래프에 적힌다). 명령을 직접 줄 수도 있다 (`--agent "claude --model sonnet"`). `--name`은 멀티플렉서의 목록에 보일 이름이고 기본은 노드 id다.
- 기다릴 때는 `muwi wait`(맡긴 노드가 끝나거나, 사람을 기다리거나, 막히거나, 세션이 멈추면 돌아온다. `muwi wait <id>`로 노드를 고른다), 화면을 볼 때는 `muwi peek <id>`, 말을 걸 때는 `muwi tell <id> "…"`.
- 맡은 세션은 끝났거나 막혔을 때 `muwi tell "<결과나 막힌 점>"`으로 맡긴 세션에 알린다 (그 세션에 방법이 전달된다).
- 끝난 노드를 맡았던 터미널은 그대로 둔다. 사람이 정리하라고 하면 `muwi tidy`로 닫는다. 세션이 닫혀 멈춘 노드는 `muwi resume <id>`로 이어 한다 (하던 대화를 다시 열 수 있으면 그 대화를, 아니면 새 대화를 띄운다).

### 맡길 때 지시에 넣을 것

맡은 쪽은 이 대화를 모른다. 서브에이전트든 새 세션이든 아래를 넣는다.

- 작업 위치: 저장소·worktree의 절대 경로와 브랜치
- 할 일과 범위, 읽을 문서(티켓·기획서 링크, 작업 폴더의 파일 경로)
- 결과를 어디에 남길지 (작업 폴더의 파일)
- 사용자가 정해 둔 원칙 중 그 일에 해당하는 것. 맡은 쪽은 이 대화에서 읽은 skill을 모른다

맡은 쪽은 계획을 새로 만들지 않는다. 맡은 일을 쪼개야 하면 `muwi add <id> "<제목>" --after <앞 노드>`로 같은 계획에 노드를 넣는다.

## 기록을 맞게 남기려면

muwi는 일하는 방식을 정하지 않는다. 어디서 작업할지, 무엇을 누구에게 확인받을지, 무엇을 승인받고 할지는 사용자의 skill과 지침에 있다. 여기 적는 것은 기록이 사실과 맞으려면 필요한 것뿐이다.

- **시작을 먼저 적는다.** 훅은 skill을 읽는 순간에 "지금 하고 있는 노드"를 같이 적는다. 그래서 노드의 일을 하기 전에 `start`를 적어야 한다. 다 하고 `start`와 `done`을 한꺼번에 적으면 그 노드에는 "기록 없음"으로 남고, 그동안 읽은 skill은 노드 밖으로 빠진다.
- **끝난 것만 끝났다고 적는다.** 맡긴 쪽이 끝났다고 한 것만으로 `done`을 적지 않는다. 결과를 직접 확인하고 적는다.
- **사람을 기다릴 때는 `wait`로 적는다.** 그래프에서 "응답 대기"가 되고 목록 맨 위로 온다.
- **다시 하는 일은 같은 노드를 다시 `start`한다.** 회차가 올라가고, 회차마다 누가 했는지와 읽은 skill이 따로 남는다. 처음에 무엇이 있었는지가 지워지지 않는다.
- **다른 일은 다른 작업에 적는다.** 같은 대화에서 하던 작업과 상관없는 일을 시키면 새 이름으로 계획을 적는다. 하던 작업의 노드를 연 채로 다른 일을 하면 그 일의 기록이 그 노드에 붙는다.
  - 같은 작업: 그 작업에서 시킨 일(`--request`)을 이루는 일. 리뷰 반영, 다시 확인, 빠뜨린 단계, 시킨 일의 범위 안에서 사용자가 고쳐 달라고 한 것.
  - 새 작업: 새로 시킨 일. 같은 대화, 같은 저장소, 같은 주제여도 시킨 일이 다르면 새 작업이다. 예: 문서 용어 정리를 하다가 "Provider로 감싸게 바꿔 줘"는 코드를 바꾸는 새 일이다.
  - 헷갈리면 새 작업으로 적는다. 한 그래프에 다른 일이 섞이면 사람이 흐름을 읽을 수 없다.
  - 넘어가기 전에 하던 작업의 남은 노드를 정리한다 (이미 끝낸 일이면 `done`, 하지 않을 일이면 `muwi remove`). 남겨 두면 그 작업은 맡은 세션 없이 "멈춤 · 다른 작업으로 감"으로 남는다. 넘어갈 때 남은 노드가 있으면 muwi가 알려 준다.
- **적는 명령은 이 세션이 붙어 있는 작업에 적힌다.** 처음 계획을 적거나 `--work`를 한 번 붙이면 붙는다. 붙은 작업이 없으면 `--work <이름>`이 필요하다. muwi가 폴더를 보고 짐작하지 않는다.
- **계획을 통째로 다시 낼 때는 지금 계획에서 시작한다.** `muwi show`로 지금 노드를 보고 그 위에 고친다. 이미 시작했거나 끝난 노드가 빠져 있으면 받지 않는다. 다른 세션이 넣은 노드일 수 있다.
- **띄운 세션은 그대로 둔다.** muwi는 스스로 닫지 않는다. 사용자가 정리하라고 하면 `muwi tidy`로 끝난 노드를 맡았던 세션을 닫는다.

작업하면서 남길 파일(요구사항 정리, 리뷰 결과, 스크린샷)을 둘 곳이 필요하면 작업 폴더 `~/.muwi/<작업>/`을 쓸 수 있다. 기록과 한 폴더에 있어서 나중에 같이 볼 수 있다.

## 보기

```sh
muwi status          # 작업 목록. 사람을 기다리는 작업이 위. 오래된 작업은 접혀 있다 (--all로 전부)
muwi show <작업>     # 노드, 걸린 시간, 누가 했는지(세션·새 세션·서브에이전트), 읽은 skill, 계획이 바뀐 이유, 문제 표시
```

## 지난 작업의 문제를 진단할 때

사용자가 "브랜치 이름이 틀렸네, 왜 그랬는지 봐줘"처럼 물으면 추측하지 말고 기록을 본다.

1. `muwi show <작업>`으로 그 일이 일어난 노드를 찾는다. 사용자가 짚은 곳은 `muwi flag <id> "<무엇이 문제였는지>"`로 표시해 둔다.
2. 그 노드에서 무엇이 있었는지 읽는다. 다시 한 노드는 회차별로 나온다. 문제가 생긴 회차를 본다.
   - **읽은 skill**: 그 회차를 하는 동안 읽은 것. `이미 읽은 상태`는 같은 세션이 앞에서 읽어 내용을 갖고 있다는 뜻이라 다시 부르지 않은 게 정상이다.
   - **읽은 skill: 없음**: 훅이 보고 있었는데 읽지 않았다. `이미 읽은 상태`에도 없으면 그 skill 없이 일한 것이다.
   - **읽은 skill: 볼 수 없었음**: 그 세션에서 훅이 돌지 않았다. 읽었는지 알 수 없으니 "안 읽었다"고 결론 내리지 않는다. 훅이 왜 안 돌았는지(muwi를 넣기 전에 연 세션, 그 도구에 커넥터를 넣었는지, Node 버전)를 먼저 본다. 이런 세션은 서브에이전트가 한 일도 세션이 한 것으로 적히므로 "누가 했는지"도 믿지 않는다.
   - **기록 없음(시작과 끝을 한꺼번에 적음)**: 하는 동안의 기록이 없다. `이미 읽은 상태`와 "노드 밖에서 읽은 skill"을 같이 보고, 그래도 모르면 결과물로 판단한다.
   - **(확실하지 않음)**: 읽을 때 같은 쪽이 노드 여러 개를 하고 있어서 이 노드의 것인지 확실하지 않다.
   - **누가 했는지**: 서브에이전트와 새 세션은 빈 상태에서 시작한다. 맡긴 세션이 읽어 둔 skill은 그쪽에 없다. `(서브에이전트)`가 붙은 skill은 서브에이전트만 읽은 것이고 맡긴 세션에는 내용이 남지 않는다. "서브에이전트 N개가 도움"은 세션이 직접 하는 동안 서브에이전트가 떴다는 뜻이다.
   - **맡긴 말**: 새 세션에 맡긴 노드는 `muwi run`에 준 말이 기록에 남는다. 서브에이전트에게 준 말은 남지 않는다.
   - **세션이 닫힘**: 끝나지 않았는데 그 노드를 하던 세션이 사라졌다. 일이 끝났는지는 기록으로 알 수 없으니 결과물로 확인한다. 이어서 하려면 `muwi node <id> start --work <작업>`으로 이어받는다 (같은 회차로 이어진다).
   - **계획이 바뀐 기록**과 **빠진 노드**: 그 노드가 왜 생겼고 왜 없어졌는지.
   - **걸린 시간**, 결과 한 줄.
3. 원인이 어느 층인지 가른다.

| 기록에서 보이는 것 | 고칠 곳 |
| --- | --- |
| 필요한 skill을 읽지 않았거나 엉뚱한 노드에서 읽었다 | 그 skill의 `description` (언제 읽어야 하는지가 드러나게) |
| skill을 읽었는데 규칙을 잘못 적용했다 | 그 skill의 내용 |
| 맡긴 쪽이 필요한 것을 모르고 일했다 | 맡길 때 준 말. 반복되면 사용자의 skill에 "맡길 때 알려 줄 것"을 적는다 |
| 계획 자체가 이상했다 | 사용자의 skill이나 지침 (그런 일의 계획에 꼭 들어가야 할 것을 적어 둔다) |
| 하면 안 되는 일을 했다 | 그 AI 도구의 권한 설정이나 사용자가 둔 훅 (muwi는 명령을 막지 않는다) |

4. 고칠 곳과 고칠 내용을 사용자에게 제안한다. 승인하면 그 skill이나 지침이 있는 저장소에 수정 PR을 만든다. skill이나 지침을 승인 없이 고치지 않는다.

기록으로 알 수 없는 것도 있다. skill을 읽고도 무시했는지, 읽지 않았지만 맞게 했는지는 보이지 않는다. 그럴 때는 결과물(커밋, 화면)을 직접 확인한다.

## 주의

- `plan.json`과 `events.jsonl`을 직접 고치지 않는다. `muwi`로만 적는다.
- `muwi` 명령이 없으면 기록 없이 평소대로 진행하고, 설치가 필요하다고 한 번 알린다.
- 사용자가 muwi를 업데이트하라고 하면 `muwi update`를 실행한다 (최신판을 받고 훅·그래프 칸·커넥터까지 맞춘다). 새 판이 나왔다는 알림을 전하는 것 말고는 먼저 업데이트를 권하거나 실행하지 않는다.
- 사용자가 터미널에서 `muwi`를 쓰거나 그래프를 보고 싶어 하면 `muwi setup`을 실행한다. 터미널용 명령과, 붙은 터미널 연결과 보기(그래프 칸 등)를 넣는다. 실행 전에 무엇을 넣는지 알린다.
- 보기가 사용자의 화면 배치를 바꾸자고 안내하면(`muwi setup`의 출력, 보기가 더한 명령의 `--status`), 무엇이 바뀌는지 알리고 사용자에게 묻는다. 화면은 사용자가 꾸민 것이므로 동의 없이 바꾸는 명령을 실행하지 않는다. 명령의 사용법을 볼 때는 `muwi --help`나 `muwi <명령> --help`를 쓴다 (실행되지 않는다).
- 기록은 일을 대신하지 않는다. 노드를 끝냈다고 적기 전에 실제로 끝났는지 확인한다.
